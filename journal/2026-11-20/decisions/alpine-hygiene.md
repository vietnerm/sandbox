# D44 — Rootfs-alpine pristine + AL5 cài trên bản sao (issue #80, class vacuous/churn)

## Bối cảnh

Phiên 8 đo được 2 vấn đề ở `rootfs-alpine/` (tracked trong git từ `42f3273`, #21):
1. **AL5 vacuous**: DB apk đã chứa `P:acpid-openrc` ⇒ `apk add` + `apk info -e`
   exit 0 mà không chứng minh đường cài — CI xanh giả theo nghĩa test-pass-vì-state.
2. **Churn**: mỗi `make test` trên cây dev làm mutate tracked files (apk ghi
   DB/world/files) — diff dư khi commit PR, drift tích lũy.

## Root cause (đo được)

- Suite alpine dùng binary thô `minict <rootfs>` — mount **IN PLACE**, không copy
  (khác wrapper `minict.sh up --rootfs` vốn `cp -a` per-instance từ D43).
- `apk add <file>.apk` LUÔN ghi constraint `><identity-hash>` vào
  `/etc/apk/world` + block vào DB — apk-world(5): *"A constraint against a
  specific identity hash is specified with the `><` operator. These constraints
  are generated by apk-add(8) when a package filename is added."* — đúng dạng
  dòng corrupt `acpid-openrc><Q1W3l08syrWte8…` đo được trong world tracked.

## Quyết định

1. **Rebuild pristine từ tarball pin** (không sửa surgical DB): `rm -rf
   rootfs-alpine && mkrootfs-alpine.sh` — sha256 pin 3.22.8 khớp
   (`2d7f46af…`, verify lại 2026-11-20). Diff git = chính xác tập cleanup:
   M `etc/apk/world`, M `lib/apk/db/installed`, M `lib/apk/db/scripts.tar`,
   D `etc/init.d/acpid`, D `etc/conf.d/acpid`, D `opt/local-repo/acpid-openrc.apk`.
2. **AL5/AL6 cài trên bản sao `cp -a`** trong WORK dir + **anti-vacuous 2 bước**:
   `apk info -e` phải FALSE TRƯỚC install (rootfs nhiễm ⇒ FAIL đúng class #80),
   install, TRUE sau install. Shared rootfs 0 write ⇒ hết churn.
3. **AL6 env-aware**: gói không download được (CDN) ⇒ PASS(env-blocked) —
   sửa latent bug (trước đây AL5 env-blocked PASS nhưng AL6 đỏ giả vì file
   chưa được cài).
4. **AL9 mới — pristine guard**: DB/world không biết gói test-only, không
   artifact apk-cài trong shared rootfs, churn probe `git status --porcelain
   rootfs-alpine` không đổi trong suốt suite (env-blocked khi không git).
   Suite alpine 8 → **9 case**; `make test` 113 → **114**.

## Sửa giả thuyết của issue #80 (evidence-based)

- **`usr/bin/tree` KHÔNG phải nhiễm**: tarball minirootfs 3.22.8 pin chứa sẵn
  `./usr/bin/tree` (symlink applet busybox — verify trực tiếp tarball
  `tar -tzf` + sha256 pin khớp). Giữ nguyên như pristine — nếu bỏ sẽ lệch
  chuẩn tarball. (Issue ghi "file mồ côi" — sai ở phần này; `P:tree` không có
  trong DB vẫn đúng vì đó là applet symlink, không phải gói.)
- **`R:acpid` trong DB** (1 dòng) = file `etc/logrotate.d/acpid` thuộc gói
  busybox pristine — bình thường, không nhiễm.

## Trade-off

- Rebuild > surgical: chuẩn hóa TRỌN bộ drift, re-producible từ pin;
  surgical chỉ sạch 1 loại nhiễm.
- `cp -a` per-suite (~8.6 MB, < 1 s) > overlayfs: không đụng runtime minict;
  GĐ2 mục 3 (overlayfs rootless) landed thì suite có thể chuyển — ghi roadmap.
- **Reforest defer** (không track 430 file): CDN dependency + thời gian CI mỗi
  run vs 4.13 MiB pack — đánh giá lại khi GĐ2 storage landed.

## Hệ quả

- Mọi test tương lai muốn apk mutate phải dùng bản sao hoặc `minict.sh up
  --rootfs` (wrapper copy riêng — precedent PT4/D43).
- Dev tree có rootfs drift cũ: `rm -rf rootfs-alpine && bash
  sandbox/mkrootfs-alpine.sh rootfs-alpine` (1 lệnh, không cần PR).
