# Research — 2026-11-20 (Phiên 9, issue #80: alpine rootfs hygiene)

## Vấn đề

Rootfs-alpine tracked trong git đã ở trạng thái "đã chạy test": DB apk chứa
`P:acpid-openrc`, world chứa dòng constraint `acpid-openrc><…>` (mồ côi), file
`etc/init.d/acpid`, `etc/conf.d/acpid`, symlink orphan `usr/bin/tree`,
`opt/local-repo/acpid-openrc.apk` đều bị track từ commit `42f3273` (#21). Hậu quả:
AL5 exit 0 vì gói đã trong DB (vacuous — không chứng minh đường cài apk), và
mỗi lần `make test` trên cây dev làm mutate tracked files (churn, diff dư khi PR).

## Nguồn (đã verify link, curl 200)

1. **apk-world(5) — apk-tools official repo** (`raw.githubusercontent.com/alpinelinux/apk-tools/master/doc/apk-world.5.scd`, 200):
   `/etc/apk/world` = danh sách CONSTRAINT của package selection. Đoạn quan trọng:
   *"A constraint against a specific identity hash is specified with the `><`
   operator. These constraints are generated by apk-add(8) when a package
   filename is added."* — đúng cơ chế nhiễm: AL5 cũ chạy
   `apk add /opt/local-repo/acpid-openrc.apk` trực tiếp trên shared rootfs ⇒
   apk-add ghi constraint `><<identity-hash>` vào world + block `P:acpid-openrc`
   vào DB. Giải thích trọn vẹn dòng world corrupt `acpid-openrc><Q1W3l08syrWte8…`.
   Bài học: file-based `apk add` LUÔN mutate world/DB — không bao giờ chạy trên
   rootfs cần giữ pristine.

2. **kernel.org overlayfs** (`docs.kernel.org/filesystems/overlayfs.html`, 200):
   model copy-on-write — layer dưới (lower) chỉ đọc, mọi write đi vào layer trên
   (upper). Đây là pattern chuẩn ngành để dùng một rootfs "template" cho nhiều
   run: template không bao giờ bị ghi. Trade-off: overlayfs thực sự cần mount
   (userns mountns được, GĐ2 mục 3 "overlayfs rootless" đã có trong roadmap);
   ngày hôm nay dùng `cp -a` per-suite-run (~10 MB, đo < 1 s) là đủ và không đụng
   runtime minict. Khi GĐ2 mục 3 landed, suite alpine có thể chuyển từ `cp -a`
   sang overlayfs per-instance бесплатно.

3. **cp(1) — man7.org** (`man7.org/linux/man-pages/man1/cp.1.html`, 200):
   `cp -a` = `--archive` (preserve ownership khi caller có quyền — với single-uid
   mapping D20, mọi file thuộc caller-uid, `cp -a` giữa cùng uid không đụng
   chown(2) ⇒ không EPERM, ownership `0:0`-trong-ns giữ nguyên tương đối).
   Là cơ chế copy an toàn cho rootfs single-uid (đã precedented: `minict.sh up`
   làm private copy `cp -a` per-instance từ D43 — cùng pattern, máy chủ-side).

## Trade-off đã cân nhắc

- **Sửa surgical DB** (strip block `P:acpid-openrc` bằng python) vs **rebuild
  pristine từ tarball pin**: chọn rebuild (`rm -rf` + `mkrootfs-alpine.sh`) —
  tarball pin sha256 (3-mirror verified, D20) chuẩn hóa TRỌN bộ drift (không chỉ
  acpid-openrc — apk add có thể đã đụng var/cache, ld.so.cache…), re-producible,
  diff git cho thấy chính xác tập cleanup. Surgical chỉ sạch đúng 1 loại nhiễm.
- **Reforest** (không track 430 file, CI tự build rootfs): DEFER — trade-off
  CDN dependency + thời gian build mỗi CI run vs 4.13 MiB pack; issue #80 đề
  xuất chỉ "cân nhắc khi làm". Giữ tracked + dọn pristine; đánh giá lại khi GĐ2
  overlayfs landed (khi đó rootfs template trở thành artifact build, không phải
  source).
- **AL6 phụ thuộc file cài bởi AL5**: giữ nguyên coupling (AL6 test đúng ý
  "ownership của file apk-cài") nhưng chuyển cả hai lên bản sao + thêm nhánh
  env-blocked cho AL6 khi CDN fail (trước đây AL6 sẽ đỏ giả khi CDN outage
  sau khi AL5 env-blocked PASS — latent bug cùng họ #75/#55).

## Áp dụng cho minict

1. Tracked `rootfs-alpine/` về trạng thái pristine từ tarball pin 3.22.8
   (rebuild + diff chỉ còn đúng tập cleanup).
2. AL5 (và AL6) cài vào **bản sao `cp -a`** của rootfs trong WORK dir — shared
   rootfs 0 write ⇒ hết churn; anti-vacuous 2 bước: `apk info -e` phải FALSE
   TRƯỚC install (bắt đúng class vacuous của #80), TRUE sau install.
3. Case mới **AL9 "rootfs pristine guard"**: assert host-side DB/world/artifacts
   sạch + churn probe `git status --porcelain rootfs-alpine` không đổi trong
   suốt suite — regression guard cho đúng class bug #80 (chạy mọi nơi, không
   cần tun/CDN).
4. Mở rộng: mọi test tương lai muốn apk mutate phải dùng bản sao hoặc instance
   qua `minict.sh up --rootfs` (wrapper đã copy riêng — precedent D43/PT4).
